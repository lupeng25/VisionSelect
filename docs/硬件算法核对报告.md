## 结论

基础几何、像元、匀速拖影和常用图像载荷换算基本正确，但当前校核不能视为完整的硬件可用性证明。已经复现快门误判、三维轮廓数量低估及三维距离与视场资料配对错误；定焦近距离估算的校核状态也需要收紧。光源目前主要依赖人工实拍确认，尚无完整的照明计算。

本次完成 Google 搜索、厂商原文核对和真实 Rust API 数值复现。共记录 23 项对照，其中 14 项与独立基准一致、9 项存在差异。差异包含同一缺陷的不同反例、模型边界和工程策略，不能解释为九个独立算法错误。

## 已确认的问题

### 1. 高优先级：混合快门被当成真正的全局快门

位置：[运动快门判断](D:/code/VisionSelect/crates/vision-core/src/engine.rs:353)。证据编号：A1、A2。

当前代码以字符串包含 `global` 或“全局”作为通过条件。因此以下两种实际目录值都会通过：

| 目录快门值 | 内置条数 | 运动状态下的当前结果 |
| --- | ---: | --- |
| `Rolling/GlobalResetRealease` | 22 | 全部通过 |
| `Rolling/GlobalResetRelease` | 2 | 全部通过 |

例如 iRAYPLE AE3504CG000E：设置速度 100 mm/s、曝光 50 μs 后，`shutter` 校核返回 `passed`。原厂规格表确实采用上述混合模式名称，拼写 `Realease` 也来自原文，不应仅靠改拼写处理。[iRAYPLE AE3504CG000E 原厂规格表，第 2 页](https://file.irayple.com/dataSheet/en/AE3504CG000E_Datasheet_2025-08-18.pdf)

GRR 属于滚动快门变体：各行同时开始曝光，但结束时间不同；需要配合适当的闪光和同步条件。设备支持 GRR 并不代表当前方案已经满足这些条件。[Basler 电子快门说明](https://docs.baslerweb.com/electronic-shutter-types)

同一分支还会把非空字符串 `Unknown` 判为冲突。目录有 3 条该值，已以 OPT-CC1-C250-UG3-01 复现 `failed`；正确语义应为“待确认”。

建议：显式区分 Global、Rolling、GRR、未知及可切换模式；区分设备支持的模式与实际启用的模式。缺少闪光窗口、脉宽和同步依据时，GRR 保持待确认。普通滚动快门的运动能力也应结合闪光条件判断。

这里确认的是“运动快门”单项误判；没有宣称整个方案的所有项目均通过。

### 2. 高优先级：三维资料把近端距离与中间视场配对

位置：[Gocator 2320 内置资料](D:/code/VisionSelect/resources/data/three_d_cameras.json:861)、[同截面视场选择](D:/code/VisionSelect/crates/vision-core/src/engine.rs:488)。证据编号：C5。

原厂 Gocator 2300 规格表第 2 页将 CD 标为设备到近端测量平面的距离，近端对应视场范围的较小值。2320 的 CD 是 40 mm、近端视场 18 mm、量程 25 mm、远端视场 26 mm。当前资料却将 `referenceDistanceMm = 40` 与 `xFovReferenceMm = 22` 配对。22 是两个视场端值的平均值，原厂表并没有将其定义为 40 mm 处的视场。[LMI Gocator 2300 原厂规格表及测量示意图](https://lmi3d.com/wp-content/uploads/2025/05/DATASHEET_Gocator_2300_US_WEB.pdf)

实际复现：选择 Gocator 2320，工作距离 40 mm、需求宽度 20 mm。接口以 22 mm 返回“当前截面 X 覆盖：通过”，按原厂近端 18 mm 应为覆盖不足。

同一规格表内七款设备均复现相同问题：

| 型号 | 原厂近端距离 / mm | 原厂近端视场 / mm | 程序在该距离采用的视场 / mm |
| --- | ---: | ---: | ---: |
| Gocator 2320 | 40 | 18 | 22 |
| Gocator 2330 | 90 | 47 | 66 |
| Gocator 2340 | 190 | 96 | 145 |
| Gocator 2350 | 300 | 158 | 261.5 |
| Gocator 2370 | 400 | 308 | 497.5 |
| Gocator 2375 | 650 | 324 | 667 |
| Gocator 2380 | 350 | 390 | 825 |

该问题主要来自资料的几何语义配对。代码虽然没有自行插值，却信任了一个配错截面的输入值。单独检查公式不足以发现它。

建议：为距离和视场保留共同的截面及测量基准；先以有来源的归一化修正层处理已确认记录，保留原始资料及来源。近端、参考截面、远端各自应有明确对应关系，不能把区间均值作为厂家公开参考值。本次没有改写原始资料。

### 3. 轮廓数量采用目标间距，低估实际采样及容量

位置：[轮廓数量计算](D:/code/VisionSelect/crates/vision-core/src/engine.rs:582)、[容量提示及指标](D:/code/VisionSelect/crates/vision-core/src/engine.rs:705)。证据编号：C1、C2、C3。

当前 `ceil(扫描长度 / 目标间距)` 计算的是满足目标间距的最少轮廓数，却标为“采集轮廓”，并用于缓存提示。实际设置可能采得更密。

| 参数 | 定时触发反例 | 编码器触发反例 |
| --- | --- | --- |
| 设备 | Gocator 2320 | Gocator 2320 |
| 扫描长度 | 300 mm | 300 mm |
| 目标间距上限 | 0.05 mm | 0.05 mm |
| 匀速轴速度 | 40 mm/s | 40 mm/s |
| 触发设置 | 1,000 Hz | 标定 100 mm / 4,000 脉冲，每轮廓 1 脉冲，1,600 Hz |
| 实际空间间距 | 40 / 1,000 = 0.04 mm | 100 / 4,000 = 0.025 mm |
| 按设置预计轮廓数 | 7,500 | 12,000 |
| 当前软件结果 | 6,000 | 6,000 |

上述数量假定无丢触发、起点触发、扫描区间为 `[0, L)`，与代码自身声明一致。若把编码器反例长度改成 3,000 mm，应有 120,000 条；代码算成 60,000 条，因此漏掉自身设置的“超过十万条”容量提醒。

正确计算关系：定时匀速采集为 `N = ceil(L × f / v)`；编码器按空间触发为 `Δy = 标定距离 / 标定脉冲数 × 每轮廓脉冲数`、`N = ceil(L / Δy)`。LMI 的触发说明同样以速度、空间间距和实际触发频率约束采样，且说明过高频率会丢触发。[LMI 编码器触发与丢触发说明](https://support.lmi3d.com/hc/en-us/articles/360033336991-Trigger-Drop-warnings-in-Encoder-Trigger-mode)

建议：分别显示“最低所需轮廓数”和“按设置预计采集数”；容量及处理量依据后者。加减速、触发相位、门控及丢触发另行说明。

### 4. 近距离定焦估算在工作台被过度确定地标为通过

位置：[工作台近轴模型](D:/code/VisionSelect/crates/vision-core/src/engine.rs:123)、[独立计算页高倍率提醒](D:/code/VisionSelect/crates/vision-core/src/calculator.rs:281)。证据编号：B1、B2。

当前定焦公式为 `倍率 ≈ 焦距 / 工作距离`、`视场 ≈ 传感器尺寸 × 工作距离 / 焦距`。这是一阶估算，并非一般意义上的错误公式；Edmund 也给出此形式，但明确指出倍率大于 0.1 或距离较短时误差会快速增大，机械工作距离还不能直接等同于主平面物距。[Edmund 焦距与视场说明](https://www.edmundoptics.com/knowledge-center/application-notes/imaging/understanding-focal-length-and-field-of-view/)

构造同一组输入：传感器 2,000 × 1,000 px、像元 5 μm，焦距 25 mm，工作距离 200 mm，需求宽 75 mm、无余量。估算倍率 0.125，宽视场 80 mm。工程工作台的视场覆盖返回 `passed`，独立页则返回 `unknown` 并提示只能粗选。

作为误差示例，仅在理想薄透镜且 200 mm 明确定义为主平面物距时，有限共轭关系 `1/f = 1/u + 1/v` 给出 `m = f/(u-f)`，宽视场为 70 mm；一阶值 80 mm 高估约 14.3%，足以改变 75 mm 工件的覆盖判断。该示例不代表任意真实 25 mm 镜头的实测值，也不能据此一律将机械工作距离替换为 `WD-f`。

建议：将两个页面的模型适用性判断共用；高倍率、短距离且没有实测或厂商模型时，保留估算数字并降低覆盖、采样等派生结论的确定性。

## 需要明确的工程策略和功能边界

### 编码器安全系数的含义

位置：[速度上限](D:/code/VisionSelect/crates/vision-core/src/engine.rs:580)。证据编号：C4。

标定 100 mm / 2,000 脉冲，每轮廓 1 脉冲，输入 800 Hz，轴速度 40 mm/s，实际间距恰为目标 0.05 mm。虽然空间采样和速度一致，默认系数 0.8 仍将速度上限降到 32 mm/s，判为冲突。

若设计目标是“实际间距不超过目标的 80%”，这是有意的采样裕量，相当于频率至少为最低需求的 1.25 倍。若设计目标是“相机保留 20% 频率容量”，则应对型号在当前设置下的可用最大频率施加余量。两者不能混称。目前先列为策略语义问题，不认定为无条件物理公式错误。

### 光源没有完成定量选型算法

位置：[照明实拍校核](D:/code/VisionSelect/crates/vision-core/src/engine.rs:414)。

选入光源后，当前仅生成 `unknown`，提示实拍确认反光、均匀性及对比度。这一保守处理合理，但没有计算照度或辐照度、有效照明面积、光谱匹配、闪光脉宽与占空比、驱动电流及散热。

光源功率、外形或发光面尺寸不足以确定工件上的有效光照；还需要工作距离、光学分布、工件表面、波长和环境信息。[Advanced Illumination 机器视觉照明指南](https://advancedillumination.com/a-practical-guide-to-machine-vision-lighting/)

### 三维时序和精度仍受资料条件限制

统计的是当前算法实际读取的归一化字段，而非断言厂商没有公布相关参数：

| 字段 | 267 条三维记录中非空数量 |
| --- | ---: |
| `scanRateMaxHz` | 193 |
| `zRepeatabilityUm` | 189 |
| `profileDataIntervalUm` | 121 |
| `supportsEncoder` | 218 |
| `exposureTimeMinUs` / `exposureTimeMaxUs` | 0 / 0 |
| `encoderRateMaxHz` | 0 |
| `supportsExternalTrigger` | 0 |

因此型号曝光范围、编码器最大输入频率、外部触发能力等分支，即使写有算法，也无法对这些内置资料完成型号验证。原始字段或原厂文档可能包含信息，需要补充有出处的归一化数据。

标称最大扫描频率仅是目录上限；曝光、有效区域和子采样会改变实机可用频率。默认 3 μs“读出与复位余量”是预算输入，不是实测型号参数；曝光加读出的串行预算也不能作为所有设备的通用时序定律。二维设备可能支持曝光与读出重叠。[LMI 当前设置对频率的影响](https://support.lmi3d.com/hc/en-us/articles/360033336991-Trigger-Drop-warnings-in-Encoder-Trigger-mode)、[Basler 重叠采集说明](https://docs.baslerweb.com/overlapping-image-acquisition)

快照、双目、结构光等设备目前不套用轮廓公式，保留待确认；这避免了误套模型，但不代表已经实现这些设备的完整选型。三维单个截面的 X 覆盖也不等于整个工件测量体积均可覆盖。

## 已核对正确或处理合理的部分

| 项目 | 当前处理及成立条件 |
| --- | --- |
| 传感器有效尺寸 | `像素数 × 像元 μm / 1000` 得 mm；不以英寸靶面名义值当实际对角线 |
| 双轴几何采样 | 同时覆盖宽高和单边余量；按较受约束的一轴选择比例；明确采样密度不等于测量精度 |
| 远心视场 | 固定倍率下 `FOV = 传感器尺寸 / 倍率`；改变安装距离不被当成任意调整倍率的方法 |
| 像圈 | 与传感器有效对角线比较；目录给出两个上限时取更严格值 |
| 镜头安装与景深 | 保留 C/CS 区别；远心工作距离缺容差时待确认；景深要求先确认倍率、光圈和评价标准 |
| 匀速拖影 | `速度 mm/s × 曝光 μs / (1000 × 像素当量 μm/px)`，单位正确；独立页说明全局曝光等前提 |
| 常见像素格式载荷 | Mono8、Mono12p、Mono12、RGB8 的位数与容器区分正确，MB/GB 采用十进制 |
| 编码器基础换算 | 移动距离/脉冲数、脉冲频率/每轮廓脉冲数、轴速度一致性及实际间距换算正确 |
| 三维精度字段 | Z 重复性、Z 分辨率、线性度各自处理，不把它们互相替代 |
| 缺失规格 | 多数数值字段缺失时保留待确认；快门 `Unknown` 的例外已单独指出 |

远心关系及双轴比例依据见 [Edmund 视场与倍率](https://www.edmundoptics.com/knowledge-center/application-notes/imaging/understanding-focal-length-and-field-of-view/)。景深必须关联分辨率、对比度及光圈，当前 `高度峰峰值 × 1.5` 是工程余量，并非通用光学定律。[Edmund 景深说明](https://www.edmundoptics.com/knowledge-center/application-notes/imaging/depth-of-field-and-depth-of-focus/)

例如 100 mm/s、曝光 100 μs、像素当量 10 μm/px，拖影为 1 px，与接口一致。曝光缩短可减少运动模糊，但整机还受读出与照明约束。[Basler 曝光及运动模糊说明](https://docs.baslerweb.com/optimizing-image-quality)

1920 × 1200、30 fps 时，Mono8 / Mono12p / Mono12 / RGB8 的纯图像载荷分别为 69.12 / 103.68 / 138.24 / 207.36 MB/s，均与独立换算一致。Mono12 用 16 位容器，Mono12p 用 12 位打包传输；实际型号可用格式及对齐要求仍需确认。[Basler 像素格式说明](https://docs.baslerweb.com/pixel-format)

载荷估算不包含协议、额外行填充、Chunk、压缩或文件元数据，当前界面已有说明。80% 带宽利用率属于设定裕量，不是接口标准保证；选择某个格式进行计算，也不代表当前硬件实际支持该格式。
