# 视觉参数工作台重设计方案

实施说明：六任务工作台已接入 Qt 应用，实际功能、模型边界和使用方法见 [工作台说明](parameter_workbench.md)。本文保留设计阶段的目标与后续扩展设想。

## 目标与范围

本方案对应现有“视觉参数校算”页面。用户确认以下三种工作方式都需要支持：

1. 已知视场和检测要求，推算所需相机规格。
2. 已知相机及部分光学条件，反算焦距、倍率、视场或工作距离。
3. 已有相机与镜头，校核成像、采样、运动和传输条件。

本次提供方案和交互原型，不修改应用业务代码。沿用石墨黑、银灰、低饱和蓝紫主题；重设计重点是计算任务、参数关系和判断依据。3D 轮廓采样继续位于现有 3D 模块。

## 现有页面的问题

- 输入按“需求、相机、镜头、光源”堆叠，无法直接表达“我已知什么、我要算什么”。
- 简单的视场或焦距计算也面对大量无关参数，缺少反算入口。
- 默认数字填满表单，用户无法清楚区分示例、实测、规格书数据和未知参数。
- 目标视场与当前镜头实际视场、目标像素当量与实际像素当量混在长文本中，难以对照。
- 报告段落适合留档，不能代替现场调参时的即时反馈和对照表。
- 当前 `estimatePure()` 聚合了大量判断；如果只更换卡片布局，计算方式仍然不会改变。

## 页面结构

页面名称建议改为“视觉参数工作台”，侧栏仍使用短名称“参数校算”。

| 位置 | 内容 | 操作规则 |
| --- | --- | --- |
| 顶部任务栏 | 视场与焦距、分辨率与像素当量、方案校核、远心倍率、运动与曝光、带宽与存储 | 切换计算任务，不清空已有数据 |
| 公共参数条 | 相机分辨率、像元、有效成像区域、来源 | 可手填；后续接入产品库；修改参数时明确影响哪些计算 |
| 左侧求解区 | 当前求解目标、必要输入、单位、可选约束 | 每次只展示相关字段；求解变量为只读结果 |
| 右侧结果区 | 当前主要结果、示意图、满足情况或缺项 | 先展示结果，再展示依据；不堆叠所有模块指标 |
| 下方对照区 | 标准焦距/倍率比较，或当前方案逐项校核 | 保留完整数值、约束和来源，可将结果暂存为方案 |
| 可展开区域 | 计算模型、公式、假设、详细过程 | 默认收起，但模型类型与关键限制始终可见 |

不额外增加常驻内侧导航栏。桌面采用双栏，窄窗口允许结果区下移或局部滚动，保持求解目标、输入和主要结果可达。

## 任务一：视场与焦距

支持三种明确的求解方向，使用分段按钮切换。

| 求解方向 | 必要已知量 | 主要输出 |
| --- | --- | --- |
| 求焦距 | 相机靶面、目标视场 X/Y、安装距离 | 同时覆盖 X/Y 的焦距约束，常用焦距对应的实际视场 |
| 求视场 | 相机靶面、焦距、距离 | 实际视场 X/Y、倍率、像素当量 |
| 求工作距离 | 相机靶面、焦距、目标视场 X/Y | 同时覆盖 X/Y 所需的距离估算及机械余量检查 |

目标视场支持直接输入，也可由工件尺寸与单边余量推导；一旦采用推导方式，不再允许目标视场和工件尺寸互相矛盾地同时编辑。

结果始终区分“需求视场”和“实际视场”。相机宽高比固定时，两个方向必须同时覆盖，不能分别反推出两个独立倍率后仍显示一个有效镜头结论。

普通镜头提供清楚的模型来源：

- 首期为“近轴粗算”，直接显示估算标识。示意图展示目标区域与实际覆盖，不画成可供加工的安装图。
- 有规格书曲线或实测数据时，优先使用相应数据，并显示适用范围与插值条件。
- 现有薄透镜估算不能继续把机械工作距离无提示地当作主平面物距。若保留薄透镜模型，应单独命名物距并说明参考平面，不能静默改变既有算法含义。

选择 16、20、25、35 mm 等比较项后，实时展示该焦距的覆盖与像素当量；这些比较项只代表参数值，不意味着产品库有对应可用镜头。

## 任务二：分辨率与像素当量

支持三种入口：

1. 视场与最小特征 → 需要多少像素。用户显式填写“每个最小特征要求覆盖多少像素”，可使用带说明的经验预设，不能隐藏倍率系数。
2. 已有相机与实际视场 → X/Y 像素当量、像素密度、特征覆盖像素数。
3. 实测长度与图像像素距离 → 标定像素当量。记录测量方向及该标定适用的视场位置。

显示 X/Y 分辨率需求，不只显示总百万像素。像素当量、特征可分辨性和测量精度分开命名；像素当量满足目标不等于完整测量误差满足要求。测量误差预算作为可选校核，明确需要标定、光学、算法和机构等信息。

## 任务三：已有方案校核

先输入或选择“当前相机、当前镜头、实际安装条件”，再添加需要校核的约束。结果使用逐项表格：

| 校核项 | 要求 | 当前值 | 状态 | 依据或待补资料 |
| --- | --- | --- | --- | --- |
| X/Y 视场 | 目标覆盖 | 实际/估算视场 | 满足或不满足 | 实测、镜头规格或近似模型 |
| 采样 | 目标像素当量 | X/Y 实际像素当量 | 满足或不满足 | 有效成像区域及倍率 |
| 安装距离 | 实际安装位置 | 镜头支持范围 | 满足、不满足或待补 | 规格书最小距离、标称距离和容差 |
| 靶面覆盖 | 传感器有效对角线 | 镜头像圈 | 满足、不满足或待补 | 镜头像圈规格 |
| 曝光与运动 | 允许拖影 | 预测拖影 | 满足、不满足或待补 | 运动方向、速度、像素当量、曝光时间 |
| 传输 | 所需吞吐 | 有效链路容量 | 满足、不满足或待补 | ROI、像素格式、帧率和链路信息 |
| 光学分辨能力/景深 | 工程要求 | 可用规格或估算 | 待补或有限结论 | MTF、光圈、倍率、评价标准等 |

总体摘要按优先级显示：存在不满足项 → 信息不完整 → 已填写的校核项满足。最后一种状态不使用“系统精度已保证”等超出证据的表述。

参数来源分别显示为手动、产品库、规格书或实测。缺少数据时不能用零替代，也不能把“没有执行校核”显示成通过。

## 任务四：远心倍率

支持“倍率求视场”“视场求倍率”“视场与采样要求求倍率范围”。结果显示可行倍率区间；若要求相互冲突，直接指出没有可行区间，以及可以调整的视场、相机或采样条件。

远心镜头的工作距离作为规格约束；不提供通过任意改变工作距离调整视场的交互。标称景深必须带适用条件，缺少条件时不作确定判断。

## 任务五：运动与曝光

支持求最大曝光、预测拖影、反算允许速度。必要量包括运动方向、相应方向的物方像素当量以及允许拖影像素数。速度为零时显示“无运动拖影约束”，不输出无穷大曝光时间。

光源强度、快门方式、读出时间和触发节拍为独立约束。运动拖影条件通过不代表亮度足够，也不直接保证目标帧率能够达到。

## 任务六：带宽与存储

输入有效输出分辨率、帧率、传输像素格式、有效链路容量及可选协议开销。像素格式明确区分 Mono8、Mono12 紧凑打包、Mono12 按 16 bit 容器输出、RGB8 等，不能只输入一个模糊的“位深”。

主要结果为单帧数据量、每秒传输量、持续采集存储量；必要时才显示利用率。MB、GB 使用十进制口径，MiB、GiB 使用二进制口径，界面不可混用。传输格式与主机处理后的格式不同，应分开估算。

## 公共交互规则

- 用户先选“求什么”，再填写已知量；不提供任意勾选一堆未知量的通用方程求解器。
- 3–6 项必要输入完成后即可得到当前任务的结果；库选型、光源类型、表面材料不能成为计算焦距的前置条件。
- 标准控件支持键盘连续输入与单位切换，正常输入实时更新；临时空值或不完整小数不立即弹窗。
- 未知参数显示“未填写”。示例通过显式“载入示例”操作进入，并标注示例来源；新建任务不自动伪装成已选硬件。
- 修改上游数据时立即更新结果；缺少必要量时清除对应结论。若必须保留历史结果，明确标记“待重新计算”。
- 每个任务保存自己的求解方向和输入。切换语言、密度和页面不丢失输入，不能按控件顺序位置恢复数据。
- 将当前结果加入 A/B 比较时保存独立快照，编辑 B 不改变 A；比较包括输入、结果、假设与未知项。
- 可复制参数表及计算依据；后续可显式应用到二维需求页，列出将覆盖的字段，不自动串改其他任务。

## 公式与边界约定

内部统一使用 mm、µm、px、s 和 byte，并在输入/输出边界转换。

| 关系 | 计算约定 |
| --- | --- |
| 有效靶面 | 未分箱、方形像元条件下，Sx = Nx × p / 1000，Sy 同理；ROI 与分箱需显式记录 |
| 固定倍率 | 实际视场 = 有效靶面 / M；像素当量 = 有效像元尺寸 / M |
| 双向覆盖 | M 上限 = min(Sx / 目标视场 X, Sy / 目标视场 Y) |
| 远心采样约束 | M 下限 = p / 允许物方像素当量；下限大于上限时无解 |
| 特征采样 | 允许物方像素当量 = 最小特征 / 每特征像素数；X/Y 所需分辨率分别向上取整 |
| 标定像素当量 | 实测长度 / 对应像素距离；该局部标定不自动证明全视场精度 |
| 沿单轴匀速运动 | 曝光上限 = 允许拖影像素数 × 该轴像素当量 / 物方速度，先统一长度单位 |
| 原始传输数据 | 单帧字节数按实际像素格式和对齐方式求得，乘帧率得到吞吐；开销与主机处理另计 |

矩形视场需同时检查两个方向。若支持旋转相机、非方形像元、分箱或斜向运动，应增加对应模型字段和测试后再开放，首期界面不暗示已经支持这些情况。

## 具体落地步骤

1. 冻结现有算法行为。为 `estimatePure()` 的典型输入保留回归基线，记录薄透镜近似、工作距离定义及经验系数，避免重构时静默改变原来的二维选型结果。
2. 增加独立计算接口，例如 `src/selection/ParameterCalculator.h/.cpp`。按视场、采样、远心、曝光、传输和逐项校核建立输入输出结构；值、单位、有效性、来源、假设分开保存。缺项采用显式可空数据。
3. 增加 `ParameterWorkspaceState`，保存相机上下文、各计算任务输入、求解方向和比较快照。为当前页面提供明确的状态导出与恢复接口，替换在 `MainWindow.cpp` 中按子控件顺序捕获该页面的方式。
4. 重构 `PureCalculationPage` 为工作台容器，先实现视场与焦距、分辨率与像素当量、已有方案校核三个核心任务。复用现有主题与通用控件；每个任务使用独立的小面板，主页面不继续堆叠一份巨型表单。
5. 接入远心倍率、运动曝光和带宽存储三个任务。全部模块共用同一套单位、状态和来源显示规则。
6. 接入产品库参数的显式导入和手动覆盖，随后完成 A/B 快照与复制导出。参数库缺少字段时保留缺项，不用模型名或标称 MP 推测光学能力。
7. 最后迁移景深、畸变和完整误差预算等高级校核。必须先明确规格条件、允许弥散圆或其他评价标准；暂不具备条件的项目显示待补资料。
8. 在 `tests/test_selection.cpp` 增加纯计算、边界和单位测试，在 `tests/test_ui.cpp` 增加切换求解目标、部分输入、状态保留及对比快照测试，再进行构建、编码检查和实际 Qt 视觉验收。

## 验收样例

- 2448 × 2048、3.45 µm 方形像元且无分箱：有效靶面为 8.4456 × 7.0656 mm。
- 采用显式近轴粗算，目标视场 120 × 80 mm、距离 300 mm：完整覆盖的焦距上限约 21.114 mm。选择 20 mm 时估算视场为 126.684 × 105.984 mm、像素当量 51.75 µm/px。界面保留近似标识，不能将距离值当成加工尺寸。
- 上例要求像素当量不大于 50 µm/px：20 mm 比较项几何覆盖满足，但采样不满足；不能只显示一个绿色通过。
- 视场 120 × 80 mm、最小特征 200 µm、每特征 4 px：X/Y 分辨率下限为 2400 × 1600 px；不能仅比较总 MP。
- 像素当量 50 µm/px、速度 500 mm/s、允许拖影 0.5 px：最大曝光为 50 µs。速度为零时显示无运动拖影约束。
- 2448 × 2048、Mono8、30 fps、无协议开销：单帧 5,013,504 byte，吞吐 150.40512 MB/s。改为按 16 bit 输出时原始吞吐翻倍。
- 未填写镜头像圈或工作距离范围：相应项显示待补资料，已能计算的视场和采样结果仍可见。
- 清空必要输入后，不保留过期的正常结果；切换任务和中英文后，输入、单位与当前求解方向完整恢复。

## 技术依据

- [Edmund Optics：焦距、视场与工作距离](https://www.edmundoptics.com/knowledge-center/application-notes/imaging/understanding-focal-length-and-field-of-view/)：用于核对近轴估算、主平面与机械距离的区别、固定倍率及宽高比关系。
- [Basler：图像质量与运动曝光](https://docs.baslerweb.com/optimizing-image-quality)：用于核对曝光、运动拖影以及亮度和帧率间的约束关系。
- [Basler：像素格式](https://docs.baslerweb.com/pixel-format)：用于核对传输格式与打包方式，避免把传感器位深直接当成实际输出字节数。

交互原型用于评审任务入口、正反算和逐项校核。它只包含有限的示例计算，产品库连接、完整光学模型、持久化和导出仍属于后续实现范围。
