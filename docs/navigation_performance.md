# 页面切换性能修复

## 问题与原因

2026-09-12 在本机复现首次打开视觉参数工作台和 3D 相机页面时的明显停顿。原有开发产物使用 Debug 应用及 Debug Qt 库；大型页面先构造完整的无父级控件树，再挂入主窗口，导致多轮样式、字体和布局传播。此外，候选计算页面每次进入都会重新查询目录和填充结果表。

## 实现调整

- 页面直接在工作区父级下创建；工作台字段、任务面板、滚动内容和 3D 面板直接绑定其最终父级，减少整棵控件树反复挂载。
- 候选计算复用当前需求的相机估算和镜头候选集合。需求变化、目录维护或主动点击重算时重新计算；切换候选相机时复用已查询的镜头集合。
- 工作台返回时保留已生成的结果表、输入和 A/B 快照；字段编辑、任务切换和数据导入仍走原有刷新流程。
- 重复点击当前导航项直接返回；只更新状态发生变化的导航按钮和工作流指示。
- 已完成的空结果与尚未计算分开记录，避免仅因切回空结果页就再次启动计算；后台计算期间切回页面时复用已有等待界面。
- 修正 MSVC Release 预设的输出目录，使其使用 `build/windows-msvc2022-release/`，与 Debug 产物分开。日常运行使用 Release 可执行文件。

## 测量记录

环境为 Windows 11、Qt 6.10.1、MSVC x64、中文舒适密度、1440 × 900 逻辑窗口。计时从导航按钮点击开始，到一次待处理 UI 事件处理结束；不含后台选型完成的等待，也不代表显示器合成器的实际呈现时间。以下为本机单次记录，硬件和运行负载会影响绝对耗时。

| 首次进入页面 | 修复前 Debug | 修复后 Debug | 修复后 Release |
| --- | ---: | ---: | ---: |
| 参数校算 | 1728 ms | 522 ms | 57 ms |
| 3D 相机 | 927 ms | 546 ms | 57 ms |
| 候选计算 | 342 ms | 182 ms | 24 ms |
| 方案评审 | 156 ms | 60 ms | 7 ms |
| 参数库 | 354 ms | 283 ms | 36 ms |

修复后 Release 来回切换各页面为 3–14 ms；工作台切换到其他计算任务为 7–19 ms。同为 Debug 的数据用于观察代码调整的效果，Release 数据同时包含应用和 Qt 运行库构建类型的影响。

## 回归与视觉检查

新增 `navigationReusesPagesAndKeepsState` 回归覆盖：

1. 首次进入与多轮返回使用相同页面实例。
2. 返回候选计算时不重复写入表格，选中相机保持不变。
3. 返回工作台时不重置结果模型，输入和 A/B 快照保持不变。
4. 修改需求后自动刷新候选，主动重算仍重新生成结果。
5. 工作台内部六种任务切换仍可正常执行，并输出交互耗时。

Release 完整 CTest 已通过：算法组 56.16 秒，UI 组 19.94 秒。最后一次 150% 缩放 UI 回归通过，耗时 23.74 秒。通过真实 QWidget 渲染图手工检查导航高亮、3D 页布局、工作台窄窗口滚动和中英文文字适配；并修正窄窗口切页后仍显示上一工作流步骤的状态问题。图像验证未操作系统窗口拖拽或贴靠。

在配置好 Qt 和开发者 PowerShell 后可运行：

```powershell
.\build.ps1 -Toolchain MSVC -Configuration Release -Test
$env:VISIONSELECT_UI_CAPTURE_DIR = "$PWD\.codex_tmp\navigation-review"
ctest --test-dir build/windows-msvc2022-release -R '^VisionSelectUiTests$' --output-on-failure
```

产物：`build/windows-msvc2022-release/bin/VisionSelect.exe`。
