# 三维修复方案与验证

## 目标与范围

修复算法核对报告中的 C1-C5：实际轮廓数量、缓存提示、编码器采样裕量语义，以及 Gocator 2300 系列七款设备的距离与视场配对。相机快门和二维定焦模型不属于本次范围。

## 数据与接口约束

- 保留 `resources/data` 全部原始文件和用户导入记录。
- 只对型号、来源和错误几何字段均匹配的内置资料应用修正；新资料库、旧资料库及旧方案快照均可生效，无需用户重新导入。
- 修正近端/远端距离，移除没有原厂依据的参考截面配对，记录修正依据。原厂基准为 CD 与近端 FOV，远端距离为 CD 加 MR；不插值中间截面。
- 保留方案 JSON 与 SQLite 格式。旧快照保留原值，计算和报告使用明确记录的修正规则；用户导入或自行修改的几何字段不被覆盖。
- `profiles` 改为按实际设置预计的采集数量，新增最低所需轮廓数与实际 Y 间距指标；缓存提醒依据预计采集量。
- 安全系数继续表示采样间距裕量：建议实际间距不超过目标间距乘系数。物理采样不足判冲突；仅未达到建议裕量时单独待确认，避免与相机能力冲突混淆。

## 实施与依赖

1. 在 Rust 核心增加可追溯且可重复应用的数据修正层，供资料库读取和扫描计算共用。
2. 修复定时与编码器数量公式、半开区间边界和容量提醒，并区分硬性采样约束与建议裕量。
3. 调整三维指标、输入标签及必要的布局；同步报告，使数值可解释。
4. 添加 Rust 数值与旧资料库/旧快照回归测试，添加连接真实 API 的界面用例。
5. 执行常规检查、视觉检查和桌面构建，记录结果。

依据：[LMI Gocator 2300 原厂规格表](https://lmi3d.com/wp-content/uploads/2025/05/DATASHEET_Gocator_2300_US_WEB.pdf)、[LMI 编码器触发说明](https://support.lmi3d.com/hc/en-us/articles/360033336991-Trigger-Drop-warnings-in-Encoder-Trigger-mode)。已在此前核对中查看完整规格表、脚注及测量示意图。

## 验证与完成条件

- Gocator 2320 在 40 mm 处采用 18 mm 视场，20 mm 需求判覆盖不足；七型号近/远端均与原厂表一致，中间未公开截面待确认。
- 定时反例返回 7,500 条，编码器反例返回 12,000 条；3,000 mm 扫描返回 120,000 条并触发容量提醒。
- 目标间距 0.05 mm、编码器实际间距 0.05 mm、速度与频率一致时，硬性采样约束通过；默认 0.8 建议裕量单独提醒。
- 新建、旧库、已保存快照、导入副本及报告均验证；用户自定义记录与原始资料保持不变。
- 执行 `cargo fmt --all --check`、`cargo test --workspace`、`npm run build`、`npm test`、`npm run test:e2e`、UTF-8 检查及桌面构建。
- 记录三维导航、指标布局、文字适配和视觉检查结果；交付可运行的新构建。

## 验证结果

已完成，日期为 2026-09-26。
