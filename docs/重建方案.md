# Rust 工程重建方案

## 目标与范围

用户已选定以 Rust 为核心、React/TypeScript 为界面的独立桌面应用。本项目使用 Tauri 2 封装，完全移除旧 C++、Qt、CMake 运行与构建依赖。仅硬件资源沿用；旧工程和未提交改动先归档，不再参与新构建。

## 架构

- vision-core：Rust 数据仓储、导入、方案模型、光学与三维校核，独立测试。
- vision-server：仅用于浏览器开发与端到端验证的本机 API，复用完全相同的 Rust 核心，不模拟计算结果。
- src-tauri：桌面入口、原生文件对话框、命令通信、操作系统数据目录。
- src：React 工程工作台、硬件资料库、方案列表与对照、校核记录。
- resources/data：原始硬件数据，不修改任何字段或文件内容。

## 产品流程

围绕一份方案工作：选择设备、编辑现场条件、即时查看成像与逐项校核。设备库提供四类硬件检索、分页和规格详情。方案保存参数与设备快照；参考方案独立保存。未知规格始终显示待确认，不将采样等同测量精度。

## 数据与退出条件

新数据库与旧程序用户目录隔离，提供旧 SQLite 产品库与 3D JSON 的导入入口，不修改源库。内置 CSV/JSON 以编译资源分发，首次启动写入新库。导入先预览、再事务提交，方案按版本校验。

完成 Rust 单元测试、前端类型检查、使用真实 Rust 服务的交互测试、桌面打包和视觉检查；检查全部硬件资源 SHA-256 与归档基线一致。UI 验证涵盖导航、参数布局、中文长型号、窄窗口和不同缩放。未验证的平台与部署条件必须明确记录。
